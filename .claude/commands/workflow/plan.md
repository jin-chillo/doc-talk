# Plan Mode 자동 진입

이 명령어를 실행하면 **Plan Mode**로 전환됩니다. Plan Mode에서는 코드 수정 없이 체계적인 작업 계획을 먼저 수립합니다.

> **Plan Mode 진입 방법**:
> - 자동: 이 명령어 실행 시 자동 전환
> - 수동: `Shift+Tab` 또는 채팅 입력창에서 Plan Mode 토글

---

## 계획 수립 프로세스

작업을 시작하기 전에 다음 4단계를 통해 체계적인 계획을 수립합니다.

### 1단계: 요구사항 분석
- 사용자의 요청사항을 명확히 파악
- 기능 요구사항과 비기능 요구사항 구분
- 제약사항 및 전제조건 확인
- 불명확한 부분은 질문을 통해 명확화

### 2단계: 영향 범위 파악
- 수정이 필요한 파일 및 모듈 식별
- 의존성 관계 분석 (영향받는 코드 확인)
- 데이터베이스 스키마 변경 여부 확인
- API 변경사항 및 하위 호환성 검토
- 테스트 코드 수정 범위 파악

### 3단계: 구현 전략 수립
- 작업을 논리적 단계로 분해
- 각 단계의 우선순위 및 순서 결정
- 필요한 기술 스택 및 라이브러리 선정
- 코드 아키텍처 및 디자인 패턴 결정
- 성능 및 확장성 고려사항 반영

### 4단계: 리스크 식별
- 예상되는 기술적 난제 식별
- 잠재적 버그 및 엣지 케이스 파악
- 보안 취약점 검토
- 성능 저하 가능성 분석
- 마이그레이션 또는 롤백 전략 수립

## 계획 완료 후 다음 단계

계획 수립이 완료되면 다음과 같이 진행합니다.

### 1. 사용자 승인 요청
```
위 계획을 검토해 주세요.
- 계획에 동의하시면 "진행해줘" 또는 "OK"를 입력해주세요.
- 수정이 필요하면 구체적인 피드백을 주세요.
```

### 2. 구현 모드 전환
- 사용자 승인 후 **Plan Mode 해제** (`Shift+Tab` 또는 자동)
- 일반 모드에서 계획에 따라 순차적으로 구현 진행
- 각 Phase 완료 시마다 진행 상황 보고

### 3. 진행 중 조정
- 예상치 못한 문제 발견 시 계획 재검토
- 필요 시 사용자에게 대안 제시 및 재승인 요청

## 사용 예시

### 예시 1: 간단한 기능 추가

**요청**: "사용자 프로필에 생일 필드를 추가해줘"

**Plan Mode 출력**:

| 항목 | 내용 |
|------|------|
| **목적** | User 모델에 생일 필드 추가 및 UI 반영 |
| **예상 소요 시간** | 30분 |
| **영향받는 파일** | 3개 (models/User.ts, migrations/, components/UserProfile.tsx) |
| **리스크 레벨** | 낮음 |

**작업 계획**:
- [ ] Phase 1: 데이터베이스 스키마 수정
  - [ ] User 모델에 birthDate 필드 추가 (optional)
  - [ ] 마이그레이션 파일 생성 및 실행
- [ ] Phase 2: API 업데이트
  - [ ] GET /api/users/:id 응답에 birthDate 포함
  - [ ] PUT /api/users/:id에 birthDate 유효성 검증 추가
- [ ] Phase 3: UI 구현
  - [ ] UserProfile 컴포넌트에 생일 입력 필드 추가
  - [ ] 날짜 포맷 표시 (YYYY-MM-DD)

**리스크**: 기존 사용자 데이터는 birthDate가 null → 기본값 처리 필요

---

### 예시 2: 복잡한 리팩토링

**요청**: "인증 시스템을 JWT에서 OAuth2로 마이그레이션해줘"

**Plan Mode 출력**:

| 항목 | 내용 |
|------|------|
| **목적** | JWT 기반 인증을 OAuth2.0으로 마이그레이션 |
| **예상 소요 시간** | 4-6시간 |
| **영향받는 파일** | 15개 이상 (auth/, middleware/, config/, tests/) |
| **리스크 레벨** | 높음 |

**작업 계획**:
- [ ] Phase 1: OAuth2 라이브러리 설정
  - [ ] passport.js 및 OAuth2 전략 설치
  - [ ] 환경변수 설정 (CLIENT_ID, CLIENT_SECRET)
  - [ ] Provider 설정 (Google, GitHub 등)
- [ ] Phase 2: 기존 JWT 로직 유지하며 OAuth2 병행
  - [ ] OAuth2 라우트 추가 (/auth/oauth/google)
  - [ ] 기존 JWT 로직은 deprecation 경고만 추가
- [ ] Phase 3: 데이터베이스 마이그레이션
  - [ ] User 테이블에 oauthProvider, oauthId 컬럼 추가
  - [ ] 기존 사용자 계정 연동 로직 구현
- [ ] Phase 4: 테스트 및 롤백 준비
  - [ ] OAuth2 플로우 통합 테스트 작성
  - [ ] 롤백 스크립트 준비

**리스크**:
- **리스크 1**: 기존 사용자 세션 무효화 → 대응: 점진적 마이그레이션 (JWT와 OAuth2 동시 지원)
- **리스크 2**: 외부 Provider 장애 시 로그인 불가 → 대응: 폴백 메커니즘 (이메일 로그인 유지)
