# Interview Mode - 대화형 문답 진행

이 커맨드는 사용자와 대화형 문답을 통해 정보를 수집하고, 수집된 정보를 바탕으로 분석 및 결과를 도출합니다.

## 문답 모드

$ARGUMENTS

**사용 가능한 모드:**
- `requirements` - 요구사항 수집
- `codegen` - 코드 생성 가이드
- `troubleshoot` - 트러블슈팅
- `onboard` - 온보딩 설정

---

## 모드별 문답 프로세스

### 1. Requirements Mode (요구사항 수집)

**목적**: 프로젝트/기능 요구사항을 체계적으로 수집

**문답 흐름**:
```
Q1. 어떤 기능/프로젝트를 만들고 싶으신가요?
    → 핵심 목적 파악

Q2. 이 기능의 주요 사용자(타겟)는 누구인가요?
    → 사용자 페르소나 정의

Q3. 반드시 포함되어야 하는 핵심 기능은 무엇인가요? (3-5개)
    → 필수 기능 목록

Q4. 있으면 좋지만 필수는 아닌 기능이 있나요?
    → 선택적 기능 목록

Q5. 기술적 제약사항이 있나요? (사용 언어, 프레임워크, 호환성 등)
    → 기술 스택 제약

Q6. 기존 시스템과 연동이 필요한가요?
    → 통합 요구사항

Q7. 성능/보안 요구사항이 있나요?
    → 비기능 요구사항

Q8. 데드라인이나 우선순위가 있나요?
    → 일정 제약
```

**출력 형식**:
```markdown
## 요구사항 정의서

### 프로젝트 개요
- **목적**: [수집된 내용]
- **타겟 사용자**: [수집된 내용]

### 기능 요구사항
#### 필수 (Must Have)
1. [기능 1]
2. [기능 2]

#### 선택 (Nice to Have)
1. [기능 1]

### 비기능 요구사항
- **성능**: [요구사항]
- **보안**: [요구사항]
- **호환성**: [요구사항]

### 기술 스택
- [제약사항 및 권장 스택]

### 통합 요구사항
- [외부 시스템 연동]

### 우선순위
- [일정 및 우선순위]
```

### 2. Codegen Mode (코드 생성 가이드)

**목적**: 원하는 코드를 정확히 생성하기 위한 정보 수집

**문답 흐름**:
```
Q1. 어떤 종류의 코드를 생성하고 싶으신가요?
    (컴포넌트/API/유틸리티/모델/테스트 등)
    → 코드 유형 결정

Q2. 사용할 언어/프레임워크는 무엇인가요?
    → 기술 스택 확인

Q3. 이 코드의 주요 역할/책임은 무엇인가요?
    → 핵심 기능 파악

Q4. 입력값(파라미터)은 무엇인가요? 타입도 알려주세요.
    → 인터페이스 정의

Q5. 출력/반환값은 무엇인가요?
    → 반환 타입 정의

Q6. 에러 케이스는 어떤 것들이 있나요?
    → 예외 처리 범위

Q7. 참고할 기존 코드나 패턴이 있나요?
    → 코드 스타일 참조

Q8. 테스트도 함께 생성할까요?
    → 테스트 포함 여부
```

**출력 형식**:
```markdown
## 코드 생성 명세

### 기본 정보
- **유형**: [컴포넌트/API/유틸리티 등]
- **언어**: [언어/프레임워크]
- **파일 위치**: [권장 경로]

### 인터페이스 설계
\`\`\`typescript
// 입력
interface Input {
  [수집된 파라미터]
}

// 출력
interface Output {
  [수집된 반환값]
}
\`\`\`

### 핵심 로직
1. [로직 단계 1]
2. [로직 단계 2]

### 에러 처리
- [에러 케이스 1]: [처리 방법]
- [에러 케이스 2]: [처리 방법]

### 참고 패턴
- [기존 코드 참조]

---
**다음 단계**: "코드 생성해줘" 입력 시 위 명세 기반으로 코드 생성
```

### 3. Troubleshoot Mode (트러블슈팅)

**목적**: 문제 상황을 체계적으로 파악하여 해결책 도출

**문답 흐름**:
```
Q1. 어떤 문제가 발생했나요? (증상을 설명해주세요)
    → 문제 증상 파악

Q2. 에러 메시지가 있다면 공유해주세요.
    → 에러 로그 수집

Q3. 이 문제가 언제부터 발생했나요?
    → 발생 시점 확인

Q4. 문제 발생 전에 변경한 것이 있나요?
    → 원인 추정

Q5. 문제가 항상 발생하나요, 간헐적으로 발생하나요?
    → 재현 조건 파악

Q6. 이미 시도해본 해결 방법이 있나요?
    → 시도된 해결책 확인

Q7. 관련 코드나 설정 파일을 보여줄 수 있나요?
    → 코드 컨텍스트 수집

Q8. 예상되는 정상 동작은 무엇인가요?
    → 기대 동작 정의
```

**출력 형식**:
```markdown
## 트러블슈팅 분석

### 문제 요약
- **증상**: [설명]
- **에러 메시지**: [있는 경우]
- **발생 시점**: [시점]
- **재현성**: [항상/간헐적]

### 원인 분석
#### 가능한 원인 (우선순위순)
1. **[원인 1]** - 확률: 높음
   - 근거: [분석]
2. **[원인 2]** - 확률: 중간
   - 근거: [분석]

### 해결 방안
#### 즉시 시도
1. [해결책 1]
   \`\`\`bash
   # 실행 명령어
   \`\`\`

#### 원인별 해결책
- **원인 1의 경우**: [해결 방법]
- **원인 2의 경우**: [해결 방법]

### 추가 조사 필요
- [추가로 확인할 사항]

---
**다음 단계**: "해결해줘" 입력 시 우선순위 높은 해결책부터 적용
```

### 4. Onboard Mode (온보딩 설정)

**목적**: 프로젝트 초기 설정을 대화형으로 진행

**문답 흐름**:
```
Q1. 어떤 종류의 프로젝트인가요?
    (웹앱/모바일/API/CLI 등)
    → 프로젝트 유형

Q2. 주요 기술 스택은 무엇인가요?
    → 기술 스택 확인

Q3. 팀 크기와 협업 방식은 어떻게 되나요?
    → 협업 컨텍스트

Q4. 코드 컨벤션이나 스타일 가이드가 있나요?
    → 코딩 표준

Q5. 테스트 전략은 어떻게 되나요? (커버리지 목표 등)
    → 테스트 요구사항

Q6. CI/CD 파이프라인이 있나요?
    → 배포 환경

Q7. 특별히 Claude가 주의해야 할 사항이 있나요?
    → 프로젝트 특수 규칙

Q8. 주로 어떤 작업을 Claude에게 요청하실 건가요?
    → 사용 패턴 파악
```

**출력 형식**:
```markdown
## 프로젝트 온보딩 설정

### 프로젝트 프로필
- **유형**: [유형]
- **기술 스택**: [스택 목록]
- **팀 규모**: [규모]

### 코드 표준
- **스타일 가이드**: [가이드]
- **컨벤션**: [주요 규칙]

### 테스트 설정
- **프레임워크**: [테스트 도구]
- **커버리지 목표**: [목표]
- **테스트 종류**: [단위/통합/E2E]

### CI/CD
- **파이프라인**: [있음/없음]
- **배포 환경**: [환경 설명]

### Claude 설정 권장사항
\`\`\`yaml
# CLAUDE.md 권장 설정
project_type: [유형]
tech_stack: [스택]
test_coverage: [목표]
conventions:
  - [규칙 1]
  - [규칙 2]
special_rules:
  - [특수 규칙]
\`\`\`

---
**다음 단계**: "CLAUDE.md 생성해줘" 입력 시 위 설정 기반으로 생성
```

## 공통 문답 원칙

### 질문 방식
1. **한 번에 하나씩**: 한 번에 한 가지 질문만 한다
2. **선택지 제공**: 가능하면 선택지를 함께 제시
3. **예시 포함**: 이해를 돕기 위해 예시 제공
4. **생략 허용**: "모르겠어요" 또는 "건너뛰기" 허용

### 응답 처리
1. **요약 확인**: 각 답변 후 이해한 내용 요약
2. **추가 질문**: 불명확한 부분은 추가 질문
3. **기본값 제안**: 답변 없을 시 합리적 기본값 제안
4. **수정 기회**: 최종 결과 전 수정 기회 제공

### 문답 종료 조건
- 모든 필수 질문 완료
- 사용자가 "충분해" 또는 "그만" 입력
- 3회 연속 "건너뛰기" 시 현재까지 정보로 진행

## 사용 예시

```bash
# 요구사항 수집
/interview requirements

# 코드 생성 가이드
/interview codegen

/interview troubleshoot

# 온보딩
/interview onboard

# 모드 미지정 시 자동 판단
/interview
```

## 문답 완료 후 자동 전환 (Auto Transition)

> **핵심 기능**: 문답 완료 시 수집된 정보와 모드에 따라 **자동으로 다음 단계로 전환**됩니다.

### 자동 전환 규칙

| 모드 | 수집 완료 후 자동 전환 | 전환 조건 |
|------|----------------------|----------|
| **requirements** | → `/plan` (Plan Mode) | 필수 질문 5개 이상 완료 |
| **codegen** | → 코드 생성 시작 | 인터페이스 정의 완료 |
| **troubleshoot** | → 해결책 순차 적용 | 원인 분석 완료 |
| **onboard** | → CLAUDE.md 자동 생성 | 기술 스택 확인 완료 |

### 자동 전환 프로세스

```
문답 완료 감지
    ↓
[전환 조건 검증]
    ├─ 필수 정보 수집 완료?
    ├─ 3회 연속 건너뛰기 아님?
    └─ 사용자 "충분해" 미입력?
    ↓
[자동 전환 제안]
    │
    ├─ requirements 모드:
    │   "요구사항 수집이 완료되었습니다.
    │    Plan Mode로 전환하여 구현 계획을 수립할까요? (Y/n)"
    │   → Y 또는 5초 무응답 시 자동 전환
    │
    ├─ codegen 모드:
    │   "코드 명세가 완료되었습니다.
    │    바로 코드를 생성할까요? (Y/n/plan)"
    │   → Y: 즉시 생성 / plan: Plan Mode 경유
    │
    ├─ troubleshoot 모드:
    │   "원인 분석이 완료되었습니다.
    │    우선순위 높은 해결책부터 적용할까요? (Y/n)"
    │   → Y: 순차 적용 시작
    │
    └─ onboard 모드:
        "온보딩 정보가 수집되었습니다.
         CLAUDE.md를 자동 생성할까요? (Y/n)"
        → Y: 설정 파일 자동 생성
```

### Requirements → Plan 자동 전환 상세

**requirements** 모드 완료 시 자동으로 Plan Mode에 진입합니다:

```markdown
## 요구사항 수집 완료

[요구사항 정의서 출력]

---

### 🔄 Plan Mode 자동 전환

수집된 요구사항을 바탕으로 구현 계획을 수립합니다.

| 항목 | 내용 |
|------|------|
| **목적** | [요구사항에서 추출] |
| **예상 영향 파일** | [분석 중...] |
| **리스크 레벨** | [평가 중...] |

[Plan Mode 4단계 프로세스 자동 실행]
1. ✅ 요구사항 분석 (Interview에서 완료)
2. 🔄 영향 범위 파악 (진행 중...)
3. ⏳ 구현 전략 수립
4. ⏳ 리스크 식별

---

계획 수립이 완료되면 승인 요청드립니다.
```

### 자동 전환 비활성화

자동 전환을 원하지 않는 경우:

```bash
# 자동 전환 없이 문답만 진행
/interview requirements --no-auto

# 전환 전 항상 확인
/interview codegen --confirm-transition
```

### 전환 흐름도

```
/interview requirements
        ↓
   [8개 질문 문답]
        ↓
   요구사항 정의서 생성
        ↓
   ┌─────────────────────┐
   │ 자동 전환 제안       │
   │ "Plan Mode 전환?"   │
   └─────────────────────┘
        ↓ Y (기본값)
   ┌─────────────────────┐
   │ Plan Mode 자동 진입  │
   │ - 영향 범위 파악     │
   │ - 구현 전략 수립     │
   │ - 리스크 식별       │
   └─────────────────────┘
        ↓
   작업 계획서 출력
        ↓
   사용자 승인 대기
        ↓ "진행해줘"
   구현 시작
```

## 병렬 분석 연계

복잡한 요구사항의 경우 Plan Mode에서 병렬 분석을 자동 제안합니다:

```markdown
## Plan Mode 분석 결과

영향받는 파일: 15개 이상
복잡도: 높음

### 권장 조치
이 작업은 복잡하므로 **병렬 분석**을 권장합니다:

1. `/parallel-review` - 기존 코드 품질/보안/테스트 분석
2. `/devil` - 리스크 사전 검토

병렬 분석을 먼저 실행할까요? (Y/n/skip)
```

## 전환 상태 저장

자동 전환 중 세션이 종료되어도 상태가 보존됩니다:

**`.claude/interview-state.json`**:
```json
{
  "mode": "requirements",
  "completed_questions": 8,
  "collected_data": { ... },
  "transition_pending": "plan",
  "created_at": "2025-01-15T10:30:00Z"
}
```

**복구 명령어**:
```bash
/interview --resume   # 이전 상태에서 이어서 진행
```
