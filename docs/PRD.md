# PRD (Product Requirements Document)
## doc-talk - PDF 문서 채팅 어시스턴트

---

## 1. 개요

### 1.1 프로젝트 정보
| 항목 | 내용 |
|------|------|
| **프로젝트명** | doc-talk |
| **버전** | 1.0.0 |
| **저장소** | GitHub Public Repository |

### 1.2 프로젝트 목적
PDF 문서를 업로드하고 자연어로 질문하면 문서 내용을 기반으로 답변하는 RAG(Retrieval-Augmented Generation) 기반 채팅 어시스턴트

### 1.3 프로젝트 목표
- **학습**: RAG 아키텍처, LLM 통합, 풀스택 개발 경험 습득
- **실용**: 실제 업무/개인 용도로 활용 가능한 도구 개발
- **포트폴리오**: GitHub에 공개하여 기술력 시연

---

## 2. 타겟 사용자

### 2.1 주요 사용자
- 기술 문서, 논문, 보고서 등을 자주 다루는 개발자/연구자
- PDF 문서에서 빠르게 정보를 찾고 싶은 사용자
- 한국어 문서를 주로 다루는 사용자

### 2.2 사용 시나리오
1. **기술 문서 학습**: SDK 문서를 업로드하고 특정 기능 사용법 질문
2. **논문 리뷰**: 여러 논문을 업로드하고 핵심 내용 비교 질문
3. **계약서 검토**: 계약서 업로드 후 특정 조항에 대한 질문
4. **회의록 분석**: 회의록 PDF에서 결정사항 추출

---

## 3. 핵심 기능 요구사항

### 3.1 필수 기능 (P0 - Must Have)

#### F1. PDF 업로드 및 처리
| 항목 | 상세 |
|------|------|
| **설명** | 사용자가 PDF 파일을 업로드하면 텍스트 추출 및 벡터화 |
| **수용 기준** | - 단일 PDF 업로드 지원<br>- 다중 PDF 동시 업로드 지원<br>- 업로드 진행 상태 표시<br>- 처리 완료 알림 |
| **제약사항** | 최대 파일 크기: 50MB, 최대 페이지: 500페이지 |

#### F2. 질의응답 (Q&A)
| 항목 | 상세 |
|------|------|
| **설명** | 업로드된 문서 내용을 기반으로 자연어 질문에 답변 |
| **수용 기준** | - 한국어 질문/답변 지원<br>- 영어 질문/답변 지원<br>- 3초 이내 첫 응답 시작 (스트리밍) |
| **제약사항** | 문서에 없는 내용은 "문서에서 찾을 수 없습니다" 응답 |

#### F3. 출처 표시
| 항목 | 상세 |
|------|------|
| **설명** | 답변 시 참조한 문서의 페이지/섹션 출처 표시 |
| **수용 기준** | - 페이지 번호 표시<br>- 관련 원문 텍스트 인용<br>- 여러 출처 시 모두 표시 |

#### F4. 대화 히스토리
| 항목 | 상세 |
|------|------|
| **설명** | 이전 대화 맥락을 유지하며 연속 질문 가능 |
| **수용 기준** | - 최근 10개 대화 컨텍스트 유지<br>- 대화 초기화 버튼 제공<br>- 세션 간 히스토리 유지 (선택적) |

#### F5. 다중 문서 관리
| 항목 | 상세 |
|------|------|
| **설명** | 여러 PDF를 관리하고 선택적으로 검색 범위 지정 |
| **수용 기준** | - 업로드된 문서 목록 표시<br>- 문서별 선택/해제 가능<br>- 문서 삭제 기능 |

### 3.2 선택 기능 (P1 - Nice to Have)

#### F6. 답변 스트리밍
- 실시간으로 답변이 생성되는 것을 표시 (타이핑 효과)

#### F7. 대화 내보내기
- 대화 내역을 마크다운/텍스트로 내보내기

#### F8. 문서 요약
- 업로드된 문서의 자동 요약 생성

## 4. 비기능 요구사항

### 4.1 성능
| 항목 | 목표 |
|------|------|
| PDF 처리 시간 | 10페이지당 5초 이내 |
| 첫 응답 시간 | 3초 이내 (스트리밍 시작) |
| 동시 사용자 | 1명 (로컬 실행 기준) |

### 4.2 사용성
- 직관적인 UI (Streamlit 기본 컴포넌트 활용)
- 한국어 인터페이스
- 에러 발생 시 사용자 친화적 메시지

### 4.3 코드 품질
- 모듈화된 구조 (관심사 분리)
- Type hints 사용
- Docstring 작성
- 단위 테스트 작성 (핵심 로직)
